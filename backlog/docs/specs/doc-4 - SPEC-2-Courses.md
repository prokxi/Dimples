# SPEC-2: Courses

Status: Accepted · Owner: prokxi · Last updated: 2026-10-11
Covers: PRD FR-10 · Milestone: M1 · Depends on: SPEC-1 (golfers, security)

## 1. Goal

Golfers enter golf courses with their tees, ratings and holes once, and everyone can reuse them for
events. The course model gives later specs (events, match play) everything they need to calculate
handicaps and allocate strokes, for 18 holes and for 9 holes.

## 2. User stories

- **US-1** As a golfer, I search for a course, so that I don't enter it twice.
- **US-2** As a golfer, I enter a course with its tees: Course Rating, Slope Rating, and par and stroke index per hole.
- **US-3** As the creator of a course, I correct or extend it (e.g. add a tee).
- **US-4** As the operator, I correct or remove any course, for example duplicates.
- **US-5** As an organiser (later spec), I pick a course, a tee and 18 holes, front nine or back nine for an event.

## 3. Domain model

### Course (aggregate root)

| Field | Type | Rules |
|---|---|---|
| id | `CourseId` (UUID) | Generated by the application (decision-2). |
| name | string | Required, trimmed, 2–100 characters. |
| city | string, optional | Max 100 characters. |
| country | string, optional | ISO 3166-1 alpha-2 code (e.g. `DE`). |
| holeCount | enum `HoleCount` | `NINE` or `EIGHTEEN`. Every tee of the course has exactly this many holes. |
| tees | list of `Tee` | At least one. Tee names are unique within the course (case-insensitive). |
| createdBy | `GolferId` | The golfer who created it. |
| createdAt / updatedAt | Instant | From the injected `Clock`. |

### Tee (part of the Course aggregate)

| Field | Type | Rules |
|---|---|---|
| id | `TeeId` (UUID) | Stable across edits, so events can refer to it. |
| name | string | Required, 1–30 characters (e.g. "Yellow", "White"). |
| courseRating | `CourseRating` | For all holes of the tee. 18 holes: 50.0–90.0; 9 holes: 25.0–45.0. One decimal. |
| slopeRating | `SlopeRating` | Integer 55–155 (WHS range). |
| frontNine / backNine | `NineHoleRating`, optional | Only on 18-hole tees: `{courseRating (25.0–45.0), slopeRating}`. Either both or none. |
| holes | list of `Hole` | Exactly `holeCount` holes, numbered 1…n without gaps. |

### Hole (part of Tee)

| Field | Type | Rules |
|---|---|---|
| number | int | 1…n. |
| par | int | 3–6. |
| strokeIndex | int | The stroke indexes of a tee are exactly 1…n, each used once. |
| lengthMeters | int, optional | 1–800. Stored in meters (SI). The SPA converts from yards if needed. |

Ratings are the men's ratings. Ratings per gender are out of scope for M1 (see section 8).

### Ratings for a hole selection

Events play a **hole selection**: `ALL` (all holes of the course), `FRONT_NINE` (holes 1–9) or
`BACK_NINE` (holes 10–18). The last two exist only on 18-hole courses.

`Tee.ratingFor(HoleSelection)` returns `{courseRating, slopeRating, par, holes}`:

| Selection | Course Rating | Slope Rating | Par |
|---|---|---|---|
| `ALL` | tee's Course Rating | tee's Slope Rating | sum of all pars |
| `FRONT_NINE` / `BACK_NINE` with nine-hole rating | that nine's Course Rating | that nine's Slope Rating | sum of the nine's pars |
| `FRONT_NINE` / `BACK_NINE` without nine-hole rating | tee's Course Rating ÷ 2, rounded half up to one decimal | tee's Slope Rating | sum of the nine's pars |

How strokes are allocated on nine holes of an 18-hole tee is defined in the match play spec.

### Snapshots

Events keep a **copy** of the tee data they use (ratings, pars, stroke indexes). The copy is taken
when an organiser starts the event (SPEC-3). Later edits to the course do not change started events.

## 4. Behaviour

- Every authenticated golfer can search, read and create courses. Courses are not personal data and
  are visible to all golfers.
- Only the **creator** and golfers with the role `OPERATOR` can change or delete a course. Others get 403
  (the course itself is not secret, so 403 instead of 404). If the creator deleted their account,
  only the operator can change the course.
- Changes replace the whole course (tees and holes included). Existing tees keep their ID when the
  request contains it; tees without an ID are new; tees missing from the request are removed.
- **Optimistic locking**: the request contains the `version` it is based on. If the course was changed
  in the meantime → 409.
- A course can be deleted only while no event uses it → 409 otherwise. (Until the events spec is
  implemented, deletion is always allowed.) A tee can be removed under the same rule.
- Search: by part of the name or city, case-insensitive, sorted by name, paginated.

## 5. REST API

All endpoints are under `/api/v1`, need an authenticated golfer, and return errors as `ProblemDetail`.

| Method & path | Request | Success | Errors |
|---|---|---|---|
| `GET /courses?query=&page=&size=` | `size` max 100 | 200 page of `CourseSummaryResponse` | 400 |
| `POST /courses` | `CreateCourseRequest` | 201 + `Location`, `CourseResponse` | 400 |
| `GET /courses/{id}` | – | 200 `CourseResponse` | 404 |
| `PUT /courses/{id}` | `UpdateCourseRequest` (incl. `version`) | 200 `CourseResponse` | 400, 403, 404, 409 |
| `DELETE /courses/{id}` | – | 204 | 403, 404, 409 in use |

- `CourseSummaryResponse {id, name, city, country, holeCount, teeNames}`
- `CourseResponse {id, name, city, country, holeCount, version, canEdit, tees: [TeeResponse]}`
  - `canEdit` tells the SPA whether to show "edit". The creator's identity is not exposed.
- `TeeResponse {id, name, courseRating, slopeRating, frontNine, backNine, par, holes: [{number, par, strokeIndex, lengthMeters}]}`
- Create and update requests have the same shape as `CourseResponse` without `id`, `canEdit` and `par`
  (plus `version` on update; tee `id` optional).
- All endpoints are documented with OpenAPI annotations.

## 6. Persistence (Flyway)

`V3__create_course.sql`:
- `course`: `id uuid`, `name`, `city`, `country`, `hole_count smallint`, `created_by uuid` (FK `golfer`, index),
  `created_at`, `updated_at`, `version int`. Index for the name search (`lower(name)`).
- `tee`: `id uuid`, `course_id` (FK, index), `name`, `course_rating numeric(3,1)`, `slope_rating smallint`,
  `front_course_rating`, `front_slope_rating`, `back_course_rating`, `back_slope_rating` (nullable).
- `hole`: `tee_id` (FK, index), `number smallint`, `par smallint`, `stroke_index smallint`,
  `length_meters smallint`, primary key `(tee_id, number)`.
- Validation rules are enforced in `domain`. Database constraints back up the essentials
  (not null, ranges, unique keys).

## 7. Frontend (SPA)

- **Course search** with a "create course" action when nothing fits.
- **Course form**, mobile-friendly: name, city, country, 9 or 18 holes; per tee: name, ratings,
  optional nine-hole ratings, and a hole table (par, stroke index, length in the user's unit).
  Shortcut: copy the holes from another tee of the same course (only lengths and ratings usually differ).
- **Course detail**: tees with ratings and the hole table.

## 8. Out of scope

- Importing course data from an **external API**. Planned for later: an adapter in `outbound` maps the
  provider's data into this model. Source and external ID fields are added in that spec.
- Ratings per gender (women's tees). Added later with a migration.
- 18-hole events on a 9-hole course (playing the nine twice).
- Merging duplicate courses, course photos, maps or GPS data.

## 9. Acceptance criteria

Domain
- [ ] AC-1 A course needs a name and at least one tee; tee names are unique within a course.
- [ ] AC-2 Every tee has exactly `holeCount` holes numbered 1…n; par is 3–6; stroke indexes are exactly 1…n.
- [ ] AC-3 Course Rating, Slope Rating and nine-hole ratings are checked against the ranges in section 3.
- [ ] AC-4 Nine-hole ratings are only allowed on 18-hole tees and only as front and back together.
- [ ] AC-5 `ratingFor` returns the values in the table in section 3 for `ALL`, `FRONT_NINE`, `BACK_NINE`, with and without nine-hole ratings (including rounding, e.g. 71.3 → 35.7).
- [ ] AC-6 `FRONT_NINE`/`BACK_NINE` on a 9-hole course is rejected.

Service & API
- [ ] AC-7 Every golfer can create, search and read courses; search is case-insensitive and paginated.
- [ ] AC-8 Only the creator and the operator can change or delete a course; other golfers get 403.
- [ ] AC-9 Updating keeps the IDs of existing tees, adds new tees and removes missing ones.
- [ ] AC-10 Updating with an outdated `version` returns 409.
- [ ] AC-11 Unauthenticated requests return 401; a missing course returns 404.
- [ ] AC-12 Persistence round trip (course → tees → holes) works against PostgreSQL, including optional fields.
- [ ] AC-13 All endpoints are in the OpenAPI spec.

## 10. Decisions

Decided on 2026-10-11:
- Courses are shared by all golfers; the creator and the operator can edit them.
- Events keep a copy of the tee data.
- Only men's ratings in M1.
- Optional nine-hole ratings, otherwise derived from the 18-hole ratings.
- An external course API comes later.
- Derived nine-hole Course Ratings are rounded half up to one decimal (71.3 → 35.7).
