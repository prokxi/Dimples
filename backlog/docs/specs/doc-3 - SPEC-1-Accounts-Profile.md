# SPEC-1: Accounts & Profile

Status: Accepted · Owner: prokxi · Last updated: 2026-10-11
Covers: PRD FR-1, FR-2, FR-4, FR-5 · Milestone: M1

## 1. Goal

Golfers can register, log in and out, manage their profile and official Handicap Index, change
their password and delete their account. This spec also sets up the security configuration
(session login, CSRF, password hashing) that every later feature builds on.

## 2. User stories

- **US-1** As a golfer, I register with email, password and display name, so that I can take part in series.
- **US-2** As a golfer, I log in and stay logged in on my phone, so that I am not logged out in the middle of a round.
- **US-3** As a golfer, I log out, for example on a shared device.
- **US-4** As a golfer, I enter my official Handicap Index whenever it changes, so that my matches use the right handicap.
- **US-5** As a golfer, I change my display name and my preferred distance unit.
- **US-6** As a golfer, I change my password.
- **US-7** As a golfer who forgot their password, I ask the operator to reset it (no email in M1).
- **US-8** As a golfer, I delete my account, and my personal data is removed.

## 3. Domain model

### Golfer (aggregate root)

| Field | Type | Rules |
|---|---|---|
| id | `GolferId` (record wrapping a UUID) | Generated by the application when the golfer is created (decision-2). |
| email | `EmailAddress` (value object) | Required, trimmed and lower-cased, max 254 characters, basic format check. Unique among active golfers. |
| passwordHash | string | bcrypt via `DelegatingPasswordEncoder` (`{bcrypt}…`). Never leaves the service layer. |
| displayName | `DisplayName` (value object) | Required, trimmed, 2–40 characters, no control characters. Shown to other participants. |
| distanceUnit | enum `DistanceUnit` | `METERS` or `YARDS`. Default `METERS`. Display preference only (SI storage stays). |
| handicapIndexes | list of `HandicapIndexEntry` | History, see below. Can be empty. |
| status | enum | `ACTIVE`, `DELETED`. |
| createdAt | Instant | From the injected `Clock`. |
| deletedAt | Instant, optional | Set when the account is deleted. |
| mustChangePassword | boolean | Set after a reset by the operator (see 4.6). |
| role | enum `GolferRole` | `GOLFER` (default) or `OPERATOR`. Only set in the database; there is no API to change it. |

### HandicapIndexEntry (part of the Golfer aggregate)

| Field | Type | Rules |
|---|---|---|
| id | UUID | Generated by the application. Needed to delete a single entry. |
| value | `HandicapIndex` (value object) | WHS range **+10.0 to 54.0**, one decimal place. Plus handicaps are stored as negative values (+2.3 → −2.3) and shown as "+2.3". |
| effectiveOn | LocalDate | The date from which the value applies. Not in the future. Unique per golfer. |
| recordedAt | Instant | When it was entered. |

- **Current Handicap Index** = the entry with the latest `effectiveOn` that is not after today.
- **Handicap Index on a date** = the entry with the latest `effectiveOn` on or before that date.
  Later specs (events, match play) use this to take a snapshot when an event starts. A snapshot
  does not change when the history changes afterwards.

## 4. Behaviour

### 4.1 Registration (US-1)
- Input: email, password, display name.
- Password: 10–64 characters, and at most 72 bytes in UTF-8 (bcrypt limit). No other composition rules (NIST 800-63B).
- If the email is already used by an active golfer → 409.
- On success the golfer is logged in immediately (session created) → 201.
- Registration is open to anyone.

### 4.2 Login & logout (US-2, US-3)
- JSON login with email and password, optional `rememberMe`.
- Wrong email or wrong password → the same 401 response (no hint which one was wrong).
- **Throttling**: after 5 failed attempts for an email within 15 minutes, further attempts for
  that email are rejected with 429 for 15 minutes. In memory is enough (single instance).
- **Session**: server-side HTTP session, cookie `HttpOnly`, `Secure` (outside local dev),
  `SameSite=Lax`, idle timeout 2 hours.
- **Remember me**: Spring Security's persistent-token remember-me (`JdbcTokenRepositoryImpl`,
  token table in Postgres), valid for 30 days. This keeps golfers logged in on their phone and
  across app restarts and deploys (sessions are in memory). No new dependency needed.
- Logout invalidates the session and deletes the remember-me token → 204.
- Login from a deleted account behaves like a wrong password.

### 4.3 CSRF
- CSRF protection stays enabled. `CookieCsrfTokenRepository` with a cookie the SPA can read
  (`XSRF-TOKEN`), sent back in the `X-XSRF-TOKEN` header on every changing request.
- `GET /api/v1/auth/csrf` lets the SPA get a token before the first login or registration.

### 4.4 Profile & Handicap Index (US-4, US-5)
- Golfers read and change **only their own** profile in this spec. How other participants see
  a golfer (name, Handicap Index) is defined in the series spec.
- Adding a Handicap Index entry with an `effectiveOn` that already exists replaces the value of
  that entry (typo correction).
- Deleting an entry is allowed. Event snapshots are not affected (see section 3).

### 4.5 Change password (US-6)
- Requires the current password. The new password follows the rules in 4.1 and must differ from
  the current one.
- On success: all remember-me tokens of the golfer are deleted, and the current session stays
  logged in. `mustChangePassword` is cleared.

### 4.6 Password reset by the operator (US-7)
- No email in M1. The operator (whoever runs Dimples) resets the password for a golfer, who then
  gets a temporary password from the operator, for example via messenger.
- Golfers with the role `OPERATOR` call `POST /api/v1/operator/password-resets` with the
  golfer's email. Dimples generates a random temporary password (16 characters), stores its hash,
  deletes all remember-me tokens of that golfer, and returns the temporary password once in the
  response. It is never stored in plain text or logged.
- For everyone without the role `OPERATOR` the endpoint returns 404, so it does not reveal that it
  exists. An unknown or deleted email also returns 404.
- After a reset, `mustChangePassword` is set. Until the golfer has changed their password, all API
  calls except reading their own profile, changing the password and logout return 403 with a
  ProblemDetail of type `password-change-required`.

### 4.7 Delete account (US-8, PRD FR-5)
- Requires the current password.
- Personal data is removed: email, password hash, display name and Handicap Index history are
  cleared or replaced. The golfer row stays with status `DELETED`, so past results (later specs)
  stay consistent and show "Deleted golfer".
- The session and all remember-me tokens are ended. The email can be used for a new registration.
- Later specs may block deletion (e.g. the golfer is the last organiser of a running series → 409).
  The service has a single place for these checks.

## 5. REST API

All endpoints are under `/api/v1`, JSON only, errors as RFC 9457 `ProblemDetail`.
Unless stated otherwise, endpoints need an authenticated golfer (401 otherwise).

| Method & path | Auth | Request | Success | Errors |
|---|---|---|---|---|
| `GET /auth/csrf` | public | – | 204, sets `XSRF-TOKEN` cookie | – |
| `POST /auth/register` | public | `RegisterRequest {email, password, displayName}` | 201, `Location: /api/v1/golfers/me`, `GolferResponse`, logged in | 400, 409 email taken |
| `POST /auth/login` | public | `LoginRequest {email, password, rememberMe}` | 200 `GolferResponse` | 400, 401, 429 |
| `POST /auth/logout` | yes | – | 204 | – |
| `GET /golfers/me` | yes | – | 200 `GolferResponse` | – |
| `PUT /golfers/me` | yes | `UpdateProfileRequest {displayName, distanceUnit}` | 200 `GolferResponse` | 400 |
| `PUT /golfers/me/password` | yes | `ChangePasswordRequest {currentPassword, newPassword}` | 204 | 400, 403 wrong current password |
| `GET /golfers/me/handicap-indexes` | yes | `page`, `size` (max 100) | 200 page of `HandicapIndexResponse`, newest first | – |
| `POST /golfers/me/handicap-indexes` | yes | `AddHandicapIndexRequest {value, effectiveOn}` | 201 + `Location` | 400 |
| `DELETE /golfers/me/handicap-indexes/{id}` | yes | – | 204 | 404 (also for another golfer's entry) |
| `DELETE /golfers/me` | yes | `DeleteAccountRequest {password}` | 204, logged out | 400, 403 wrong password, 409 blocked |
| `POST /operator/password-resets` | role `OPERATOR` | `PasswordResetRequest {email}` | 200 `PasswordResetResponse {temporaryPassword}` | 400, 404 (also for non-operators) |

- `GolferResponse {id, email, displayName, distanceUnit, currentHandicapIndex (nullable), mustChangePassword}`
- `HandicapIndexResponse {id, value, effectiveOn, recordedAt}`
- IDs in JSON are UUID strings.
- Handicap values in JSON are numbers; plus handicaps are negative (the SPA shows "+2.3").
- All endpoints are documented with OpenAPI annotations.

## 6. Persistence (Flyway)

- `V1__create_golfer.sql`
  - `golfer`: `id uuid primary key`, `email text` (lower-cased), `password_hash text`,
    `display_name text`, `distance_unit text`, `status text`, `role text`, `must_change_password boolean`,
    `created_at timestamptz`, `deleted_at timestamptz`, `version int`.
    Partial unique index on `email` where `status = 'ACTIVE'`.
  - `handicap_index_entry`: `id uuid primary key`, `golfer_id` (FK + index), `value numeric(3,1)`, `effective_on date`,
    `recorded_at timestamptz`, unique `(golfer_id, effective_on)`.
- `V2__create_remember_me_token.sql`: the `persistent_logins` table as Spring Security expects it.
- IDs are UUIDs generated by the application (`UUID.randomUUID()`) when an aggregate is created
  (decision-2). Spring Data JDBC sees an aggregate as new when its `@Version` field is `null`,
  so a new aggregate with an ID is inserted, not updated.

## 7. Frontend (SPA)

Depends on the frontend skeleton (separate foundation task). Screens:
- **Register** and **Login** (with "Stay logged in"), mobile-first.
- **Profile**: display name, distance unit, current Handicap Index with history and "add new value".
- **Change password**; shown automatically when `mustChangePassword` is set.
- **Delete account** with password confirmation and a clear warning.
- Footer links to the legal notice and privacy policy (the pages themselves are a separate task).

## 8. Out of scope

- Email verification, "forgot password" by email, invitations by email (PRD FR-6, M2).
- Social login, two-factor authentication.
- Profile pictures.
- Showing other golfers' profiles (series spec).
- Legal notice and privacy policy pages (separate task, content provided by the owner).

## 9. Acceptance criteria

Domain
- [ ] AC-1 `EmailAddress` is normalised (trimmed, lower-cased) and rejects invalid or too long values.
- [ ] AC-2 `DisplayName` rejects values that are blank, too short, too long or contain control characters.
- [ ] AC-3 `HandicapIndex` accepts −10.0 to 54.0 with one decimal and rejects anything else.
- [ ] AC-4 The current Handicap Index and the Handicap Index on a date follow the rules in section 3, including "no entry yet".
- [ ] AC-5 An entry with a future `effectiveOn` is rejected. An entry with an existing `effectiveOn` replaces the value.
- [ ] AC-6 Deleting an account removes all personal data and sets the status `DELETED`.

Service & API
- [ ] AC-7 Registration creates the golfer, stores only a bcrypt hash, logs the golfer in, and returns 201 with `Location`.
- [ ] AC-8 Registration with an email of an active golfer returns 409. Passwords outside 10–64 characters / 72 bytes return 400.
- [ ] AC-9 Login with a wrong password or unknown email returns the same 401. The 6th failed attempt within 15 minutes returns 429.
- [ ] AC-10 "Remember me" keeps the golfer logged in after the session expires and after an app restart.
- [ ] AC-11 Changing requests without a valid CSRF token are rejected with 403.
- [ ] AC-12 Unauthenticated requests to protected endpoints return 401 (not a redirect).
- [ ] AC-13 A golfer cannot read or delete another golfer's Handicap Index entry (404).
- [ ] AC-14 Changing the password requires the current password and ends all remember-me tokens.
- [ ] AC-15 After an operator reset, only the allowed endpoints work until the password is changed.
- [ ] AC-16 Deleting the account requires the password, logs out, and frees the email for a new registration.
- [ ] AC-17a An operator gets a temporary password for a golfer; the golfer must change it at the next login. Non-operators get 404.
- [ ] AC-17 No passwords, hashes or emails appear in logs.
- [ ] AC-18 All endpoints are in the OpenAPI spec with request/response schemas.

## 10. Decisions

Decided on 2026-10-11:
- Registration is open to anyone.
- Operator password reset through an endpoint for the role `OPERATOR` (section 4.6).
- `spring-boot-starter-validation` is added to the `pom.xml` (approved dependency).
- Application-generated UUIDs for all aggregates (decision-2).
- The security configuration in sections 4.2, 4.3 and 5 is approved.
